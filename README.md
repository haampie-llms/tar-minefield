# tar-minefield

A corpus of tar archives, each with a verdict, for tar parsers that want to be strict: which
archives they must reject because readers disagree on what they contain, which they must accept,
and what tree they must extract. [METHOD.md](METHOD.md) describes how the corpus is built; it is
a draft, and the corpus itself is not written yet.

## How strict can a parser be?

A strict parser is useless if it rejects the tarballs people download. To measure that, the
scanner reads the headers of real release tarballs from Spack, nixpkgs and live-bootstrap, and
records every feature that METHOD.md lists as an ambiguity:

Of 22692 distinct tarballs, 21944 pass every criterion. The criterion that rejects the most tarballs on its own is `number.*.leading-space`.

| dataset | assessed | pass all criteria | of latest versions | pass if `number.*.leading-space` were allowed | untar extracts |

| live-bootstrap | 171 | 163 (95.32%) | 74 (100.00%) | 171 (100.00%) | 171 (100.00%) |
| nix | 18990 | 18308 (96.41%) | 17285 (96.27%) | 18833 (99.17%) | 18912 (99.59%) |
| spack/2026-10-23-b | 1981 | 1934 (97.63%) | 960 (96.77%) | 1955 (98.69%) | 1963 (99.09%) |
| spack/2026-10-23 | 1990 | 1955 (98.24%) | 970 (97.59%) | 1971 (99.05%) | 1978 (99.40%) |

Generated by `scanner/strict.py` from 4 scans: the details are in [data/STRICT.md](data/STRICT.md).
